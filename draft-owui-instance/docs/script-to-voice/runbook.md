## Commands currently implemented

Choose **Script to Voice** and attach an FDX original. After import:

Navigation: `help` / `what next` shows the journey and current step without provider inference. `scenes` and `characters` browse the loaded source. `wrong model` explains switching to the Guide or a configured chat model. `wrong script` explains replacement; `wrong selection` / `clear selection` clears selected scope, overrides and prepared plan while retaining source, cast and audio. Navigation does not cancel an existing job. Wrong-format attachments are rejected explicitly; remove them before other commands. Attach one new FDX per message. Help/exit bypass attachments; resend the file with `Use attached script` to import it.

Step 2 now asks directly for **entire script**, **single scene** or **single character**. The scene/character choices display the relevant source list and ask a follow-up; reply with a scene number/location-time description or character name. You can also send `single scene: NUMBER` or `single character: NAME`. Resolving these choices does not use Claude; successful selection can separately prepare the Step 3 suggestions described below. Unclear descriptions/names require clarification rather than guessing. Existing selection commands below still work.

Step 3 now shows proposed voices immediately after selection, then asks whether any roles are already cast. Supply `CHARACTER: VOICE_ID` or an ElevenLabs voice link, one per line. Double-check the displayed mapping and simply reply `confirm cast` to apply the latest review; no code is needed. Suggestions, voice lines, plain yes/no and saved voice previews do not assign characters automatically. Internal selection/cast-version checks reject stale reviews. `discard cast changes` retains the last confirmed cast. The new proposal step can use the existing capped Claude allowance even after a deterministic selection; help and redisplaying a saved review do not repeat inference. Supported links are parsed without being followed or automatically importing shared voices. See the journey document for link forms and API boundaries.

Voice IDs in the casting review and voice lists now link to the corresponding ElevenLabs Voice Library entry. Login/voice access may be required; fake IDs are not linked. These are ordinary browser links and do not confirm casting or include server credentials. Public link format was checked from ElevenLabs' site; private/generated-voice browser behavior and OWUI rendering remain untested.

## Recovery and operation

Use `status` after reload/disconnection. Successful chunks are persisted immediately. Duplicate submission keys return the same job. Authentication/permission failures stop scheduling; rate limits and transient errors have bounded retries. An interrupted active provider request becomes uncertain after lease expiry and is not automatically replayed. Cancellation cannot undo provider work already accepted. The worker runs one request at a time.

Progress UI deployment: install the updated stored STV Function with `scripts/install-script-to-voice-function.ps1 -Update` (v0.3.0), and apply the service's owner-scoped `/v1/render-jobs/{id}/result` route. This change does not require restarting the worker; leave it running during an in-flight paid render. The indicator is OWUI's native animated status text and depends on injected session/chat/message event metadata and enabled status updates. Without usable events the ordinary saved-job/status fallback remains. No new model/provider credentials or budget are needed. Browser acceptance is pending; source inspection/build/startup are not animation/playback tests.

Possibly billable attempts reserve their full rendered character count against the job envelope. Explicit rate/auth rejections do not reserve speech usage. A transient/uncertain result can exhaust the envelope, stopping later scheduling rather than expanding authorized spend. A character envelope cannot alone enforce a pound-denominated account budget: configure live usage only after checking current account rates and preview charges.

Audio is decoded to consistent PCM and encoded once for assembly; originals and timing metadata are retained. Missing alignments remain null rather than fabricated. File delivery uses OWUI's owner-bound backend registration and relative content URLs. Browser playback, range requests and authenticated multi-user deployment remain acceptance gates until recorded in progress.md.

Back up both named volumes using the existing environment's backup practice. Do not use `down -v`. To roll back the feature, disable only its Function, set `STV_ENABLED=false`, and stop `script-to-voice` and `script-to-voice-worker`. Keep both data volumes and the Guide. Upgrade OWUI only after retesting its injected arguments, file APIs, ownership, registration and browser playback.
